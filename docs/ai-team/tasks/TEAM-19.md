# TEAM-19 실제 주문 결정과 가상 체결·계좌 원장 연결

- 상태: 가상 원장·실제 서비스 연결 구현, 독립 감사와 격리 회귀 검증 완료. 운영 미적용.
- 시작일: 2026-11-19.
- 사용자 목표: 실제 미국 자동매매 코드가 낸 주문으로 가상 체결, 현금, 보유 수량을 갱신하고 다음 매매 판단에 사용한다.
- 유지 조건: 현금 한도, 미체결 예약금, 기존 보유 매도 관리, 계좌 고점 대비 10% 차단을 유지한다. 10%는 차단 기준이며 갭·체결 지연 시 손실 상한 보장은 아니다.
- 범위: 테스트 소스의 결정론적 가상 브로커/계좌 원장, 실제 서비스와의 연결, 격리 재생 검사, 독립 원장 감사. 운영 연결·실주문·설정 변경·push·배포 없음.
- 기존 작업: TEAM-10~18 변경과 확보 원문을 보존한다. 시장자료 부족과 S&P 500 초과수익 미입증은 별개로 남긴다.

## 역할과 파일 소유권

- 개발/원장: BE `KiwoomUsReplayLedger.java`, `KiwoomUsReplayLedgerTest.java`.
- 개발/통합: BE 기존 `KiwoomUsProductionReplayHarness.java`, 신규 `KiwoomUsCausalReplayTest.java`.
- 독립 기획·검증: 이 문서, BE `tools/team19_audit.py`, `tools/team19_test.py`. 제품 Java 코드는 직접 수정하지 않는다.
- 총괄: 실행 경로·문서·상태 통합, JDK21 격리 Maven 실행. 에이전트는 Maven을 병렬 실행하지 않는다.
- 디자인: 제품 화면 변경이 없어 별도 UI 작업 없음.

## 검증할 인과 관계

초기 현금·기존 보유와 시간순 시장 프레임만 외부 입력으로 주고, 실제 서비스 주문이 가상 브로커에 도착한 이후 원장으로 주문·예약금·체결·잔고를 생성한다. 이후 계좌와 체결 응답은 원장으로부터 공급한다. 후속 계좌·체결·주문 성공 응답을 입력 파일로 주입해 결과를 만들 수 없어야 한다.

체결은 주문 이후의 명시적인 시장 관측과 한정된 거래 가능 수량으로 처리한다. 지정가와 스프레드·수수료·결제 규칙을 공개하고, 매수 여력과 미결제 매도대금, 매도 가능 수량을 구분한다. 실제 증권사의 체결 확률·대기열·장애를 복제했다고 주장하지 않는다.

### 독립 검토 기록

- 실제 `TradeService.placeOrder()`의 마지막 자금 검사를 실행하고, 허용된 HTTP 쓰기 경계에 도달한 주문만 원장에 등록하는 연결을 확인했다. 일반 Spring 컨텍스트·DB·스케줄러는 생성하지 않는다.
- 초기 위험 기준은 초기 원장 현금과 bid 평가 보유에서 유도한다. causal 입력은 후속 account/broker/initial_risk_equity_usd 주입을 거부한다. 프레임 시작 때 앞선 주문을 체결하고, 그 계좌와 체결을 실제 서비스의 대사·감시·판단에 공급한다.
- 독립 검토에서 현재 프레임의 quote map만 유지하면 종목이 빠졌다가 재등장할 때 이전 관측 시각 검사를 우회할 수 있음을 지적했다. 개발 담당이 `lastObservations`를 별도로 유지하고 회귀 검사를 추가했다. 동일 관측의 유동성은 다시 채워지지 않으며 관측 시각 역행을 거부한다.
- 원장은 매도대금을 즉시 매수가능 현금으로 사용하지 않고 다음 거래일 09:30 ET까지 미결제 채권으로 보관한다. 수수료는 정확한 십진수 비율이며 센트 반올림·최저수수료·매도 세금을 추가로 모델링하지 않는다. 주문 이후 정규장의 새 관측에서만 체결되며 지정가·bid/ask·제시 수량을 사용한다.
- 독립 Python 감사기는 초기 상태와 ORDER/FILL/CANCEL/SETTLEMENT/MARK 이벤트에서 현금·예약금·보유·평가액을 다시 계산한다. 체결의 주문 참조·시각·지정가·수수료·유동성을 확인하고, MARK의 보유 가격을 같은 프레임 quote의 bid와 비교한다. 보고된 최종 합계만 신뢰하지 않는다. 출처 진위·수익성 인증은 아니다.
- Python 감사기 자체의 17개 검사 통과. 첫 실행 보고서 `target/us-causal-replay/run-ae1606926c7b4dd1a43f9f3e4642c221/report.json`을 독립 실행하여 10개 원장·42개 이벤트 감사를 통과했다. 이 보고서를 변조한 현금 생성·평가액 생성·예약금 변경·중복 체결·주문 동시각 관측·수수료 변경·잘못된 평가가격 7건은 모두 거부했다.
- 기존 보유와 새 자동매수 보유의 각각 매도 경로는 지원한다. 같은 종목에 운용 도중 수동 수량을 추가하는 외부 주식 입출고 이벤트는 지원하지 않으므로 해당 혼합 상태 전이를 이번 신규 원장 검사에서 검증했다고 주장하지 않는다. 기존 실제 서비스의 같은 종목 추가 매수 차단은 유지한다.
- 가상 주문은 체결 또는 서비스 취소 때까지 유지하는 단순 모델이다. 실제 증권사의 DAY 만료·대기열·거래조건·장애·슬리피지를 복제하지 않는다. 기록된 프레임에서 일어나는 합성 테스트이며 모든 30초 관측이 자동 생성되는 역사 시뮬레이터가 아니다.
