# TEAM-25 자동 연구·가상 매매·비교와 승인 후 전략 교체

- 시작일: 2026-11-22. 상태: 구현·검증 진행.
- 사용자 요청: 연구와 가상 매매·전략 비교를 자동화하고 더 좋은 전략을 검토한 뒤 교체할 수 있게 한다. 현금 한도와 계좌 고점 대비10% 차단을 유지하고 운영에 적용하지 않는다.
- 제품 범위: 별도 로컬 연구 콘솔에서 자료 수집→고정 후보 연구→새 자료의 가상 매매→동일 조건 비교→사람의 승인→가상 운용 전략 교체를 연결한다. 실제 운영 자동매매·계좌·DB·키·설정 변경, 실제 주문, push와 배포는 포함하지 않는다.
- 자동 연구는 검토한 전략 카탈로그의 반복 평가다. 새로운 임의 코드를 AI가 생성해 운영에 넣는 기능이 아니다. 현재 카탈로그는 TEAM-24의 전략3개×위험 정책2개다. 공급 자료는 완료 일봉이며 초단타·장중 실시간 주문 검증을 주장하지 않는다.

## 역할과 파일 소유권

- 총괄: HTTP 서버·수집/스케줄 실행 진입점·통합 검사·실제 브라우저·결과 통합.
- 개발: BE `tools/research_lab/core.py`, `replay.py`, `data.py` 및 각 단위검사. 지속 저장·연구·원장·교체를 구현한다.
- 디자인/프론트: FE `UsStrategyLab.vue`, `usStrategyLabApi.js`, 별도 `strategy-lab` 진입점·개발 프록시·단위검사.
- 독립 기획/검증: 이 계획과 BE `tools/research_lab/acceptance_test.py`. 구현 담당 설명과 별개로 실제 코드와 요구사항을 대조한다.
- 기존 Java 운영 서비스와 기존 연구 결과를 수정하지 않는다. 새 화면은 운영 라우트에 붙이지 않고 로컬에서 확인한다.

## 사용자 흐름

1. 로컬 콘솔을 열면 가상 운용 전용 표시, 자료 기준일, 현재 가상 전략과 잔고·고점·차단 상태를 본다.
2. 자동 실행을 켜거나 수동으로 연구를 실행한다. 서버가 실행 중인 동안 지정된 주기로 새 완료 일봉을 확인한다. PC 종료·절전·서버 종료 시 실행되지 않는다.
3. 초기 과거 자료는 연구와 지표 예열에만 사용한다. 등록 이후 새로 관측한 일봉부터 가상 매매 성과를 별도로 쌓는다. 과거 성과를 신규 관찰 성과로 소급하지 않는다.
4. 후보별 비용 차감 수익·낙폭·거래수·관찰일수·현재 전략 대비 차이·승인 불가 이유를 확인한다. 후보가 없거나 자료가 부족하면 거래와 교체를 억지로 발생시키지 않는다.
5. 조건을 충족한 후보를 선택하고 보고서 내용을 확인한 뒤 **가상 운용 전략 교체**를 명시적으로 승인한다. 승인되지 않은 후보를 자동 적용하지 않는다.
6. 교체는 이후 데이터의 의사결정에만 적용한다. 이전 거래·잔고·고점·손실 차단을 변경하거나 초기화하지 않는다. 교체·거절·실행 실패의 이력을 남긴다.

## API 계약

로컬 API 기준 경로는 `/api/strategy-lab`이다. 기본 바인드는 백엔드127.0.0.1:13230, 프론트127.0.0.1:13130이며 운영 주소로 프록시하지 않는다.

| 요청 | 입력 | 정상 동작 |
|---|---|---|
| GET `/status` | 없음 | 자료·작업·스케줄 상태, 현재 전략/가상 원장, 최신 비교 보고서, 승인 이력 |
| POST `/cycle` | 서버가 정한 자료 사용 | 중복 실행 없이 연구·가상 원장·비교 갱신 |
| POST `/scheduler` | `enabled` boolean | 로컬 서버 자동 실행 활성/중지 |
| POST `/approve` | `candidateId`, `reportId`, `expectedRevision` | 최신 검증 결과 재확인 후 가상 전략 교체 예약·기록 |
| POST `/reject` | 같은 보고서·후보·revision | 해당 제안의 거절 기록; 운용 전략은 유지 |

상태와 응답은 camelCase JSON을 사용한다. 코어는 `paperOnly:true`와 현재 전략의 `validatedForLive:false`로 가상 연구 경계를 표시한다. 현재 가상 기준 전략은 `balanced_trend:recovery_vol`이며 운영 계좌의 실제 자동매매 전략 성과를 가져온 값이 아니다. 브라우저 버튼의 비활성화만으로 인가를 대신하지 않는다.

## 후보와 승인 조건

- 카탈로그의 전략·위험 정책·실행 소스는 버전 해시로 식별한다. 보고서는 자료 해시·코드 버전·계좌/상태 revision과 결합한다. 자료·코드·최신 보고서가 달라진 이전 승인은 거부한다.
- 연10%는 거래 비용 차감 후 목표이며 매년 또는 미래 수익 보장이 아니다. 역사 연구에서 최근 두 구간과 연속 구간의 두 비용 조건을 검토하고, 위험 기준과 함께 보고한다.
- 신규 관찰 최소60개 완료 거래일, 후보 거래 최소20건, 후보 순수익 양수·현재 가상 전략보다2%p 이상 우수, 후보 최대 낙폭10% 이하이면서 현재 전략보다1%p 이상 나쁘지 않아야 승인 후보가 될 수 있다. 이 수치는 구현을 위한 사전 최소 검토 조건이며 전략의 통계적 우위 보장이 아니다.
- 역사 조건 미달·신규 자료 부족·오래된 자료·손실 차단·현재 전략과 동일·변경된 보고서·동시 작업 중에는 승인하지 않는다. 테스트 전용 합성 자격 사례가 실제 실행의 우회 옵션으로 노출되지 않아야 한다.
- 후보의 자기 가상 계좌와 실제로 교체되는 가상 운용 계좌를 구분한다. 후보로 교체한다고 후보의 과거 잔고·고점을 복사하지 않는다.

## 위험·데이터·지속성 불변식

1. 매수는 비용 포함 결제된 현금99%와 정수 수량 한도다. 미결제 매도 대금·배당채권을 즉시 매수 자금으로 사용하지 않는다. 차입과 공매도는 없다.
2. 고점 대비10% 하락을 관측하면 영구 신규매수 차단과 청산 정책을 적용한다. 갭·비용·일중 경로 미관측 때문에 손실 상한10% 보장은 아니다.
3. 교체·재시작·자동 실행 중지/재개가 현금·보유·미결제 대금·고점·차단을 초기화하지 않는다. 기존 보유는 새 전략의 다음 판단에서 관리하며 승인 직후 임의로 전체 매도하지 않는다.
4. 이전 완료 종가로 판단하고 다음 완료 일봉의 시가로 가상 체결한다. 현재 일봉의 종가를 이미 끝난 같은 날 시가 주문에 사용하지 않는다.
5. 같은 자료를 다시 받아도 같은 날짜를 중복 체결하지 않는다. 과거 가격 수정·날짜 누락·미래 일봉·불완전 자료는 실패 처리하거나 검증 대기로 남기며 원장을 조용히 다시 쓰지 않는다.
6. 자료 원본·해시·등록 시점·진행 날짜·전략 버전·승인 이력을 지속 저장한다. 동시 실행/승인과 재시작 시에도 부분 저장이나 중복 교체가 없어야 한다.
7. 데이터 오류 시 마지막 확인 수치는 남기되 오류와 오래된 상태를 표시하고 승인·교체를 막는다. 자동 작업 오류가 운영 API 호출로 이어지는 대체 경로는 없다.
