# TEAM-20 종목 선택과 실제 주문·가상 원장 연결 검토

- 상태: 복수 종목 선택→실제 매수·매도→가상 원장 비교 및 동률 선택 결함 수정·검증 완료. 실제 시장 수익률 개선 검증은 자료 부족으로 미완료, 조건 강화안 미채택.
- 시작일: 2026-11-19.
- 사용자 목표: 종목 선택 기준의 수익성을 검토·개선하고 실제 매수·매도 코드와 가상 원장까지 연결한다.
- 유지 조건: 주문 가능 현금·미체결 예약금·계좌 고점 대비 10% 차단 유지. 운영 설정·실계좌·주문·push·배포 없음.
- 현황: 사용자에게 별도 데이터 서비스 계정이나 역사자료가 없음을 TEAM-18에서 확인했다. 기존 일봉과 SEC 2개 기업 공시만으로 당시 후보 순위·호가·Yahoo 기업 지표·지수 편입을 복원할 수 없다. 이 공백을 합성 수치로 메우고 실제 수익률이라고 표시하지 않는다.

## 역할과 범위

- 총괄: 실제 선택 코드의 재현 가능한 결함 수정, 후보 추적과 실행 경로 통합, 격리 Maven 실행, STATUS/BACKLOG 갱신.
- 개발: BE `KiwoomUsSelectionReplayTest.java`, 복수 후보의 선택→실제 주문→가상 매수·매도/계좌 시나리오.
- 독립 기획·검증: 이 문서, BE `tools/team20_analysis.py`, `tools/team20_test.py`, 독립 코드/결과 검토.
- UI 변경이 없어 디자인·브라우저 작업은 없다. 기존 TEAM-10~19 변경은 보존한다.

## 실행 전 고정하는 비교 설계

다음 세 설정을 상승 지속/선택 이후 반전 두 합성 경로에 동일하게 적용한다. 실제 시세 예측력이 아닌 선택 동작·원장 연결·설정 민감도 검사다. 결과를 본 뒤 값을 바꾸거나 유리한 경로만 보고하지 않는다.

| 설정 | minRelativeStrengthPercent | maxEntryExtensionAtr | 의도 |
|---|---:|---:|---|
| BASE | 0 | 1 | 기존 기본 선택 |
| TIGHT_EXTENSION | 0 | 0.25 | 돌파 후 추격 허용폭 축소 |
| STRONG_RELATIVE | 8 | 1 | 지수 대비 강도 조건 강화 |

- 3설정 × CONTINUATION/REVERSAL = 6개 경로. 시작 현금 10,000 USD, 수수료 10bps, 종목당 한도 10% 및 기존 위험 설정을 공통 사용한다. 현금/10% 규칙을 바꾸어 성과를 높이지 않는다.
- 후보 모집단과 각 시각 입력은 같은 시장 경로 안에서 고정하며 설정만 변경한다. 합성 후보 ALPHA/BETA는 코드의 점수·필터를 검사하기 위한 명시적 예제다.
- 첫 판단의 후보 순위/점수·선택 사유, 실제 선택 종목과 주문, 후속 실제 매도, 원장의 최종 현금/보유/미결제 자산을 연결한다.
- 별도로 후보 입력 순서 교환과 하락 시장의 매수 차단을 확인한다. 거래가 없는 경우를 누락하거나 0%를 지수 초과로 해석하지 않는다.
- 시험 결과가 좋더라도 종목 선택 모수의 운영 채택 근거로 삼지 않는다. 실제 시장자료·평가기간 분리·비용/체결 가정 검증이 추가로 필요하다.

## 독립 사전 코드 검토

- TREND 종목 점수는 지수 대비 20거래일 상대강도, 돌파 가격과 현재 매수가의 변동성 보정 거리, 호가 스프레드를 사용한다. 거래대금 순위는 동점 결정에 사용된다. 높은 점수는 미래 수익 보장이 아니다.
- `Flux.flatMap`의 호가 완료 순서로 중간 후보 배열이 만들어지고 기존 정렬은 점수·거래대금 순위까지만 비교한다. 두 값이 같은 후보가 있으면 응답 완료 순서/입력 순서에 따라 첫 종목이 바뀔 수 있다. broker 순위 파서는 중복 순위 자체를 거부하지 않는다. 동일 시장 입력의 재현성을 위한 종목/거래소 최종 비교는 수익률 개선과 구분한다.
- 최대 스프레드/돌파 이격을 0으로 직접 주입하면 점수의 0/0과 `Math.round(NaN)`으로 점수가 0이 되는 경계가 존재하지만, 정상 설정 저장은 각각 0.05/0.1 이상으로 제한한다. 일반 UI에서 발생하는 결함으로 과장하지 않으며 임의의 비정상 설정을 성과 비교에 쓰지 않는다.
- 재무 누락 시 TREND의 기술 평가 계속 동작은 현재 코드의 명시적 정책이다. 과거자료가 없다는 이유로 과거 조회 실패를 꾸며내어 그 경로를 활용하지 않는다.

## 독립 계산 방식

`team20_analysis.py`는 먼저 TEAM-19의 독립 이벤트 감사를 통과시킨다. 초기 현금과 초기 보유 × 첫 관측 bid로 초기 평가액을 검증하고, MARK별 전체 계좌 평가액과 최종 상태로 합성 수익 변화·관측 최대 낙폭을 계산한다. 체결 수수료, 매수/매도 체결 수와 주식 수량, 잔여 보유와 미결제 순매도대금도 보고한다. 미결제 대금은 자산에는 포함하지만 매수 가능한 현금으로 변경하지 않는다.

자료 종류가 synthetic이 아니거나 시장 성과 검증 완료라고 선언하면 이 계산기는 거부한다. 결과는 `PASS_SYNTHETIC_DIAGNOSTICS_ONLY`, `performance_verified=false`, `adoption_decision=NOT_ESTABLISHED_SYNTHETIC_ONLY`, benchmark 비교 null이다. 관측 사이의 가격을 만들어 최대 낙폭을 계산하지 않는다.

### 독립 실행·계산 검토

- 총괄이 실행한 최종 선택 보고서 `target/us-selection-replay/run-1d724685ebb7441281f6bcff5481e12e/report.json`을 독립 분석기로 다시 읽었다. **11개 원장·116개 이벤트**, 사전 고정 비교 6개 조합의 감사와 계산을 통과했다.
- CLI는 고정 6개 조합이 누락되거나 중복되면 거부한다. 같은 경로의 비교 간 비선택 설정·시장 MARK 시각/호가가 다르면 거부한다. 설정은 cash 10000·fee 10bps·maxOrderPercent 10과 계획한 상대강도/돌파 이격을 확인한다. 추가 순서교환/동점/하락장 회귀 예제는 `REGRESSION`으로 구분한다.
- 독립 Python 계산기 단위 검사 **14개 통과**. 현금 포함 수익률, 미결제 매도대금의 자산 반영, 수수료, 관측 고점 대비 낙폭, 잘못된 최초 평가액/최종 현금 거부, 합성 자료의 실제 자료 재명명 거부, 비교 조합 완전성·동일 조건 검사를 포함한다.

- 동점 회귀는 총괄의 수정 전 실행에서 ALPHA 기대/BETA 실제로 실패했고, 이후 종목·거래소 최종 비교 추가 후 통과했다. 이 수정은 선택의 재현성 개선이며 미래 수익성 개선이 아니다.
