- 이번 범위: 로컬 코드·격리 테스트·오프라인 평가. 운영 활성화, 실주문, 운영 DB 변경 및 푸시는 실행하지 않는다.

## 완료 기준과 기획

1. 실제 주문가능 USD 현금과 미수불가 금액/수량을 주문 직전 검증. 누락·불명확 응답은 매수차단. 원화주문/차입/시장가 매수 금지, 기존 1% 비용 여유 유지.
2. 주문 발송 전 상태를 영속화하여 재시작·결과불명 주문이 예약금/중복방지에서 빠지지 않는다.
3. 명시적으로 새 정책 활성화한 계좌의 전체 보유를 위험관리 대상으로 사용. 배포만으로 기존 수동보유가 자동청산되지 않는다.
4. USD 전체계좌 unit NAV 최고점 대비 10% 하락시 신규매수 중단, BUY 취소 및 안전한 전체보유 청산 시도. 거래정지/갭/체결오차로 최대실제손실 보장 아님.
5. 위험래치/원장은 재시작 후 유지. 입출금은 매매손익과 구분하며 현금변동으로 자동추정하지 않는다. 수동 자금이동 확인 절차의 한계를 명확히 표시.
6. 새 정책 신규매수는 TREND 신호로 제한. 기존 지표를 수익이 검증된 전략으로 표시하지 않는다.
7. 동일기간 USD·배당포함 benchmark와 비용반영 전략 NAV를 비교하는 주문없는 오프라인 평가 도구. 합성데이터 통과는 투자성과 증명이 아니다.
8. 모바일에서도 현금한도/정책/차단사유/미검증 상태를 표시. 실제 주문/외부 계좌 없이 회귀 테스트.

## 확정 API

관리자 전용 `/api/kiwoom/us/auto-trade` 하위:

- GET `/risk`: enabled, equityUsd, peakEquityUsd, drawdownPercent, limitPercent, triggered, liquidationPending, capitalFlowConfirmed, observedAt(시간대 포함), message.
- POST `/risk/activate`: confirmAllHoldings, confirmCapitalFlows 모두 true. 최신 일관된 계좌·미체결 없음 확인 후 기준 설정. 신규 매수 스위치는 꺼진 상태로 둔다. 기존 기준/발동 잠금 초기화 불가.
- POST `/risk/capital-flow-review`: required=true. 자금 이동 전에 실행. 새 매수·낙폭 판정을 보류한다.
- POST `/risk/capital-flow`: reference(최대100), amountUsd(입금+,출금−), confirm=true. 같은 참조/금액은 멱등, 다른 금액은 거부. 실제 자금 이동 후 등록한다. 주식 매매·배당은 외부 입출금이 아니다.

## 안전성 및 운용 한계

- 주문 직전 USD 현금/실제 주문가능금액/미수불가금액과 수량의 교집합을 사용하며 1% 여유를 둔다. 전체 현금은 예산 범위이며 한 번에 전액 매수한다는 뜻이 아니다. 기존 분산/종목수/건별 위험 제한을 유지한다.
- 계좌 위험평가는 ust21160의 D4 결제예정 USD 현금 + ust21070의 현재 보유수량×현재가를 사용한다. D0부터 D4까지 매수·매도 정산금 정합성, USD 통화, 누락/부채/중복종목/지원수량을 검증한다. D0 현금만 더하면 결제 전후 자산을 잘못 계산할 수 있다.
- 예수금→보유→예수금 재조회로 조회 중 자금 변동을 검출한다. 로컬 미체결 중에는 새 위험 고점을 관측하지 않고 외부/식별불능 미체결은 주문을 차단한다. 브로커의 서로 다른 API가 원자적 스냅샷임을 보장하지 않으므로 실제 계좌 대사 검증이 추가로 필요하다.
- 10% 발동은 신규매수 잠금·기존 매수취소·전보유 매도 시도다. 미확정 주문/매도가능수량 부족/휴장/거래정지/호가누락은 청산을 지연시킨다. 이미 발동했다면 예수금 조회 실패와 청산을 분리하고 최신 보유·주문 확인으로 진행한다.
- 입출금 자동감지는 없다. 사전검토 없이 입출금하면 낙폭/고점이 잘못 계산될 수 있다. 입출금 검토 중에는 새로운 낙폭 판정도 보류된다. 수동 원장 대조가 필요한 제한이며 보장형 손실상한이 아니다.
- SUBMITTING 상태와 발송시각을 HTTP 전 저장/flush한다. 재시작 후 미확정은 UNKNOWN으로 대사하며 무조건 재발송하지 않는다.
- 기존 TREND 추세·상대강도 신호는 검증 후보로 유지한다. 새로운 수익전략이나 과거시장 백테스트를 완성했다는 의미가 아니다. backend `tools/US_PERFORMANCE.md`의 CSV 평가기는 제공된 성과 원장을 비교하는 도구이며 주문 시뮬레이터가 아니다.

## 배포 메모 (미실행)

- 신규 JPA 테이블 `kiwoom_us_account_risk`, `kiwoom_us_capital_flow`; proposal 상태 SUBMITTING 추가. nas/docker는 ddl-auto update, prod는 validate이므로 사용 프로파일에 맞는 스키마 준비 필요. 운영 DB에는 접근하지 않았다.
- 배포한다면 백엔드→프론트 순서. 최초 정책 비활성으로 기존 수동보유를 즉시 인수하지 않는다. 신규 매수는 정책/TREND/최신계좌 확인이 필요하다.
- 정책 활성화부터 기존 보유의 매도 감시가 시작될 수 있다. 신규매수 시작과 별개임을 확인한다. 중지 버튼은 신규매수만 중지하며 위험 잠금을 해제하지 않는다.
- 되돌릴 기준 FE b966b33 / BE beed245. SUBMITTING/UNKNOWN 미확정 주문이 있으면 이전 버전으로 단순 롤백하지 말고 주문 대사를 먼저 완료해야 한다. 새 위험 테이블 삭제/래치 초기화는 롤백에 포함하지 않는다.
