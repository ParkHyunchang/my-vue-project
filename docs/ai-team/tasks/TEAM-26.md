# TEAM-26 연구 전략의 실계좌 승인 연결

- 시작일: 2026-11-23. 상태: 로컬 구현·격리 검증 완료, 운영 미적용.
- 사용자 요청: 연구실에서 검증한 전략을 사용자가 승인하면 실계좌 미국 자동매매에 적용할 수 있게 연결한다. 주문 가능 현금 내 매수, 기존 보유 종목 매도 관리, 고점 대비 10% 손실 차단을 유지한다. 이번에는 운영에 적용하지 않는다.
- 승인 범위: 연결 기능의 코드·화면·격리 검증. 실제 계좌 설정 변경, 실제 승인 등록, 실제 주문, 운영 DB 접근, 운영 배포·push는 포함하지 않는다.

## 현재 상태와 설계 기준

TEAM-25는 Python의 완료 일봉 ETF 연구이며 Java 운영 자동매매는 장중 순위·펀더멘털·호가·TREND 신호다. 이름이나 설정만 대응시켜서는 연구 전략을 적용한 것이 아니다. 검증된 전략·코드 버전·자료·보고서를 식별하고 실제 실행 시 동일한 선택·위험 정책을 사용하도록 연결해야 한다.

연구는 SPY·QQQ·GLD·IEF의 배당조정 종가로 지표를 산출한다. 기존 증권사 일봉의 비조정 종가로 지표를 대체하면 결과가 달라질 수 있다. 연구와 실계좌의 체결 모델도 다르므로 실제 호가·부분 체결·계좌 기존 보유를 포함하는 실행 안전성 검사와 전략 신호의 일치 검사를 구분한다.

수익성 검증 결과를 브라우저가 보낸 `eligible:true`만으로 인정하지 않는다. 신뢰된 연구 결과의 출처·무결성, 허용된 전략 버전, 보고서와 자료 날짜를 확인한다. 기본값은 연결 비활성이다. 연결 활성화와 사용자 전략 승인은 별개이며 승인이 자동매매 시작이나 위험 기준 초기화를 겸하지 않는다.

## 역할과 파일 소유권

- 총괄: API 계약 확정, 통합과 실제 실행 경계, 기록 최종화.
- 기획·검증: 이 문서, `UsStrategyBridgeAcceptanceTest`, `UsStrategyDeploymentBoundaryTest`, `UsStrategyDeploymentPersistenceTest`. 이후 검증기 개발도 분담받아 `ResearchEvidenceVerifier`와 자체 검사를 구현했다. 따라서 서명 검증기 자체 검사는 구현자 검사이며 엔진·연결 서비스에 대한 별도 담당 검토와 구분한다.
- 엔진 개발: Java `ResearchStrategyEngine`·`ResearchExecutionPlanner`·`UsResearchDeploymentGateway`, 기존 미국 자동매매 서비스 분기와 실제 자료 golden/경계 검사.
- 총괄 개발: Python 내보내기·시장파일 발행, Java 배포 승인 서비스·Entity·Repository·Controller·DTO, 전체 통합 검사.
- 디자인·프론트: 연구실 서명 보고서 내보내기, 실계좌 승인/철회 화면·API·테스트와 로컬 브라우저 대역.

## 확정 API와 실행 계약

운영 앱의 `/api/kiwoom/us/strategy-deployments` 아래에서 ADMIN 인가를 적용한다. 신규 연결 설정 `kiwoom.us.strategy-bridge.enabled`는 기본 `false`, 서명 키 파일과 시장자료 파일 경로는 기본 비어 있다. 실제 운영 값은 이번 작업에서 설정하지 않는다.

| 요청 | 입력 | 동작 |
|---|---|---|
| GET `/status` | 없음 | 기능 활성 여부, 익명 계좌 범위, revision, 보류 보고서, 승인 전략과 실행 상태 |
| POST `/imports` | `payloadJson`, `signature` | 서명·내용을 검증해 현재 계좌에 보고서 등록; 매매 시작 없음 |
| POST `/approve` | 보고서 후보 `candidateId`, `expectedRevision`, `reportId`, `version`, `confirmLive:true` | 최신 보고서·계좌·위험·진행 상태 확인 후 해당 버전만 승인; 자동매매 시작 없음 |
| POST `/revoke` | `expectedRevision` | 진행 중 판단/자동매매 중에는 거부; 승인 해제 후 이전 전략으로 자동 복귀하지 않음 |

연구실은 고정 코드 해시와 `team24-daily-v1` 실행 버전에 대한 data-only JSON을 HMAC-SHA256으로 서명한다. 키는 채팅·브라우저로 보내지 않는다. 후보 내보내기는 적격 보고서만 가능하고 fixture 모드에서는 금지한다. 시장 신호는 완료 일봉의 실제 연구 지표를 담은 서버 설정 파일로 발행한다. 실패한 수집은 이전 시장파일을 차단 상태로 바꾼다. 파일 배치·공유와 키 설정은 향후 운영 반영 때 검토할 항목이다.

Java는 서명 원문·1MiB 한도·중복 JSON 키·고정 코드/엔진·최대24시간 유효기간·최근4일 이내 완료 UTC 일봉·현금/전체 보유/10% 정책을 검증한다. 후보의 3기간×2비용과 전진 관찰 조건은 단순 `passed` 표시와 별개로 재검사한다. 승인 시 계좌 해시를 결합하고 계좌 설정 변경 시 기존 승인은 차단한다.

실행은 정규장에 직전 완료 거래일의 서명된 신호만 사용한다. 엔진은 같은 ETF 선택·위험 비중·월별 FULL/일별 EXIT·REDUCE/FUND 판단을 사용하지만 수량은 실제 계좌·현재 호가로 산출한다. 일봉 시가 체결과 실제 지정가 체결이 같다는 주장은 하지 않는다. 연구 대상 밖 기존 종목은 목표 비중0으로 매도 관리한다. 승인 화면에 이 전환 범위를 표시해야 한다.

한 번 승인한 뒤에는 비활성/철회/오류 상태에서도 기존 장중 전략으로 자동 복귀하지 않는다. 연구 전략이 정상 매도를 담당하고 전체계좌10% 긴급 청산 경로는 유지한다. 승인·일자·시장자료 해시와 연결된 실행 상태를 주문 전에 저장하며, 실패·불확실 실행은 자동 재시도하지 않고 재검토 대상으로 남긴다. 접수 이력은 체결 이력이 아니다.

## 사용자 흐름

1. 연구실에서 후보의 비용 차감 성과·낙폭·신규 관찰·현재 가상 전략 대비 차이를 확인한다.
2. 조건 미달 후보와 지원되지 않는 버전은 실제 적용 후보가 될 수 없다.
3. 실제 적용 화면에서 전략·버전·자료 기준일·보고서와 기존 보유 관리 범위를 확인한다.
4. 사용자가 실계좌 적용임을 명시적으로 확인하고 승인한다. 서버는 최신 증거와 상태 버전을 다시 검사한다.
5. 승인한 전략은 기존 실계좌 자동매매의 시작·정지·위험관리·주문 안전 검사를 통과할 때만 적용된다. 승인을 받지 않은 새 연구 결과로 자동 교체하지 않는다.
6. 적용 또는 실패의 기록을 남기며 과거 잔고·고점·차단 이력은 유지한다.

## 검증 결과

### 기획·검증 담당 결과

부모의 격리 Maven 실행에서 생성된 Surefire XML을 직접 확인했다. 담당 검사 **29개 모두 통과**, 실패·오류·생략0이다. 전체 회귀 수와 브라우저 결과는 총괄이 최종 실행 결과로 추가한다.

- `ResearchEvidenceVerifierTest` 7개: HMAC 원문 변조·다른 키·중복 키·뒤따른 JSON·기한·소스/버전·기간/비용 누락·전진 관찰 미달·위험 완화·잘못된 시장 값 거부. 검증기를 이 담당자가 구현했으므로 자체 검사로 분류한다.
- `UsStrategyBridgeAcceptanceTest` 9개: 독립적으로 ETF 동률 선택, 빈 슬롯 현금 유지, 일간 신규 승자 추가 금지, 고정 비중, 차단 상태, 기존 보유 추가매수·대상 밖 매도, 매도대금의 당일 재사용 금지, 일회성 FUND와 중복 날짜, 매도가능수량/호가 부족을 확인했다.
- `UsStrategyDeploymentBoundaryTest` 7개: 연결 비활성/철회 뒤 managed 경계 유지, 계좌 설정 변경, 다른 코드의 유효 서명, CLAIMED/FAILED 재실행 차단, 상태 보존과 자동 시작 없음, 이전 승인/동일 날짜/변경 시장 해시의 claim 거부를 확인했다.
- `UsStrategyDeploymentPersistenceTest` 3개: 실제 두 Entity와 Repository를 UUID H2 메모리 DB에서 사용했다. 별도 세션에서 승인·실행·감사 상태 유지, optimistic revision 충돌, pessimistic write lock 경합을 확인했다. 운영 DB나 전체 앱을 시작하지 않았다.
- `UsStrategyDeploymentAuthorizationTest` 3개: 실제 Spring method-security proxy로 익명/일반 USER의 상태·가져오기·승인·철회 접근이 서비스 도달 전에 거부되고 ADMIN만 전달되는지 확인했다. HTTP 인증 쿠키/CSRF 전체 흐름의 검증과는 구분한다.

정적 검토에서 권고한 시장자료 해시의 claim 결합, 승인 시 최신 시장 보고서 일치, 계좌 변경 후 잔고/위험/청산 경로 차단을 총괄·엔진 담당자가 반영했다. 기존 계좌의 고점/10% 차단을 연구 후보의 가상 잔고로 덮어쓰는 경로는 추가하지 않았다.

수량·정상 매도는 실제 현금·보유·지정가를 사용하므로 공개 일봉 시가 백테스트와 실제 체결 결과가 동일하지 않다. 부분 체결·취소 후 목표 미달과 체결 비용 차이를 실거래 수익 검증 완료로 포장하지 않는다. 실계좌 주문은 실행하지 않았다.

- 운영 HTTP 인증부터 실계좌 체결까지 검증한 것은 아니다. 브라우저 파일 업로드의 전체 연결도 별도 수행하지 않았으며 파일/서명 경계는 단위·교차 언어 검사로 확인했다.
- 승인·실행·계좌 경계, 실제 H2 저장과 Spring 권한을 검사했다. CLAIMED 상태의 미확정 실행은 자동 복구하지 않고 대조·복구 작업 전까지 차단한다.
- 서명 키·운영 설정·운영 DB·실계좌에 접근하거나 변경하지 않았고 배포/push/실제 주문 없음. 현재 실제 적격 후보0/6이라는 기존 연구 판정을 완화하지 않았다.

향후 운영 파일 전달·스키마·배포 준비 및 실제 체결 검증은 남는다. 상세 사용·장애·제한 안내: 백엔드 `STRATEGY_DEPLOYMENT.md`.
