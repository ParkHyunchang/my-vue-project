# TEAM-17 실제 의사결정 코드 재사용 검증 경로

- 상태: 격리 재생 경로 구현·독립 검토·회귀 검증 완료. 실제 시점별 자료 부족으로 성과 검증은 보류.
- 시작일: 2026-11-19.
- 목적: 별도 연구 모형과 실제 미국 자동매매 구현 사이의 차이를 줄이기 위해, 운영 의사결정 코드를 재사용하는 격리 테스트 경로와 입력자료 계약을 만든다.
- 범위: BE 테스트 하네스, 오프라인 시점별 입력자료 계약, 로직·안전경계 검증. FE 제품 UI/API 변경 없음.
- 운영 상태: 실계좌 조회·주문·활성화·배포·push 없음. 기존 실계좌 구현과 TEAM-10~16 변경을 보존한다.

## 해결할 문제

TEAM-15/16의 SPY 단순 연구는 개별 종목의 거래대금 순위·지수 편입·기업 지표·호가·상대강도·돌파를 사용하는 실제 전략 전체를 재현하지 않았다. 기존 `KiwoomUsReplayAdapterTest`도 실제 기술신호 계산은 재사용하지만 후보 선정, 주문 수량, 계좌 위험, 주문 상태 대사까지 재사용한 성과 검증은 아니다.

이번에는 실제 `KiwoomUsAutoTradeService`의 의사결정 흐름을 테스트에서 호출한다. 실제 제품 메서드를 실행했다는 사실과 입력자료가 실제 과거 시장을 재현한다는 사실은 별개다. 합성자료로 주문 경계와 정책 동작을 검증할 수 있지만, 실제 시점별 자료가 없으면 S&P 500 대비 수익률을 판정하지 않는다.

## 재사용 경계 계약

| 구간 | 확인할 사항 | 결과 표현 제한 |
|---|---|---|
| 기술신호 | 완료 일봉 검증, SPY/QQQ 비교, 상대강도·돌파·ATR | 신호 함수만 통과했다면 전체 전략 검증으로 부르지 않음 |
| 의사결정 | 실제 후보 필터·순위·최종 매수 선택 | 필터에 실제 입력을 주는지, 일부 서비스 결과를 대역으로 고정했는지 공개 |
| 주문 준비 | 현금·위험 예산·미체결·기존 보유·재검증 | 테스트에서 호출한 실제 검사와 대역으로 건너뛴 검사를 구분 |
| 위험 관리 | 고점 대비 10% 잠금, 전체 보유 관리, 잠금 후 신규 매수 차단 | 단순 설정값 확인을 실제 상태 전이 검증으로 표현하지 않음 |
| 주문·체결 | 가짜 브로커 응답과 결정론적 원장 | 실제 주문 전송·증권사 체결 품질·실거래 수익 검증 아님 |

최종 구현에서 재사용한 클래스·메서드와 대역으로 교체한 경계를 목록으로 확정한다. 브로커 `buy`/`sell`을 대역으로 바꿨다면 그 하위 통신·응답·주문가능수량 검사의 실검증을 주장하지 않는다. 프리뷰 호출만으로 매수 경로 검증 완료라고 표시하지 않는다.

## 안전 조건

- 일반 `WebApplication`, 운영 설정, `.env`, 계좌 키, 운영 DB를 사용하지 않는다. 실제 스케줄러를 부팅하지 않는다.
- 기존 JDK 21 `test-isolated.ps1`의 네트워크·DNS·자식 프로세스·비밀파일 차단을 유지한다. 실패를 피하려고 guard를 해제하지 않는다.
- 주문은 테스트 내부의 명시적 대역으로만 전달되며, 실제 브로커 클라이언트가 생성·호출되지 않도록 한다.
- 현금 99% 한도 및 계좌 고점 대비 10% 차단 정책은 변경하지 않는다. 손실 상한 보장이 아니라 도달 시 차단·청산 규칙이다.
- 자동매수와 기존 보유가 섞인 종목의 관리, 미체결 예약금, 불확실한 주문 상태를 우회하지 않는다.
- 테스트 시각·거래일은 고정한다. 호스트의 현재 장시간이나 날짜가 달라져도 같은 결과가 나와야 한다.

## 시점별 입력자료 계약

성과 검증에 사용하려면 최소한 아래 자료가 각 결정 시점에 존재해야 한다. `관측 시각`과 `당시 이용 가능 시각`을 구분하며, 나중에 확정·정정된 정보를 과거 판단에 소급하지 않는다.

- 당시 거래대금 순위와 순위 모집단, 현재가·등락률·일중 거래량, 비교에 쓰는 전일 거래량.
- 당시 S&P 500/NASDAQ-100 편입 여부. 현재 구성종목을 과거 모든 시점에 적용하지 않는다.
- 사용 당시 발표되어 있던 PER·ROE 등 기업 지표. 필터를 끄거나 대역 숫자를 넣은 실험은 해당 차이를 표시한다.
- 당시 bid/ask와 시각, 주문 시점의 재조회 자료. 일봉 시가·종가를 실제 호가처럼 바꾸지 않는다.
- 종목·SPY·QQQ의 완료 일봉과 동일 거래일 정렬, 기업행사·조정가격의 기준.
- 초기 현금·기존 보유·평균 원가·매도 가능 수량·미체결 주문, 이후 입출금·배당·기업행사 및 수수료 가정.
- 실제 거래일·세션, 신호 시점과 주문/체결 시점. 미래 가격을 신호에 넣지 않는다.
- 같은 기간의 비교 지수 자료와 가격수익/총수익 여부, 통화·비용·현금 포함 평가 방식.

필수 자료가 없거나 미래정보가 섞였으면 자료 검증은 실패 또는 불완전으로 처리한다. 완성된 합성 fixture가 있다고 실제자료 공백이 해소된 것은 아니다. 자료 계약 통과도 출처의 진위·당시 가용성을 자동 입증하지 않는다. 입력 해시와 생성 근거를 함께 남겨야 한다.

독립 검토 담당은 제품 코드와 연구 구현을 변경하지 않는다. 재현 가능한 결함과 누락은 구현 담당에게 전달하고, 총괄이 수정 후 전용 테스트를 실행한다. 실행하지 않은 검사는 통과로 표시하지 않는다.

### 독립 코드 검토 중간 기록

- 새 `KiwoomUsProductionReplayHarness`는 실제 AutoTradeService, TechnicalSignalService, AccountRiskService, AutoTradeState와 TradeService의 주문 직전 자금 검사·파서를 재사용한다. 외부 조회는 명시적인 프레임 입력으로 대체하고 주문 HTTP는 네트워크 없는 `exchangeFunction`으로 돌린다. Spring 컨텍스트·스케줄러·운영 DB를 생성하지 않는다.
- 하네스의 `MONITOR`는 스케줄러 등록이 아니라 실제 감시 메서드 직접 호출이다. 프레임 시각과 거래일 처리도 테스트 경계에서 고정한다.
- 현재 하네스는 명시적인 `NEW_POLICY_NO_PRIOR_AUTOMATION` 입력으로 신규 위험 기준·빈 주문 이력·자동매수 활성 상태로 시작하는 시험 경로다. 과거 자동매매 이력·잠금 상태를 복원하는 엔진으로 해석하지 않는다. 기존 수동 보유는 입력한 잔고에 포함할 수 있다. 대역 Repository이므로 DB 트랜잭션·영속 복구 검증도 아니다.
- 결과는 수익률·벤치마크 수익률을 null로 두고 `performance_verified=false`를 명시한다. 자료 계약 검증도 항상 `performance_allowed=false`이며 구조 통과로 성과를 승인하지 않는다.
- 독립 검토에서 자료 계약의 결정 시각과 미국 거래일 불일치, 재무 조회 상태의 명시 필요성을 전달했다. 자료 검사기는 결정 시각에서 미국 날짜를 직접 도출하도록 수정했고, 하네스도 재무 조회 상태와 실제 누락값을 명시하는 입력을 지원하도록 바뀌었다. 설정 변환 오류가 static mock 설치 전에 발생하도록 검증 순서를 보완했다. 이전 자동매매 상태를 몰래 초기화하지 않도록 신규 정책 전용 초기화 조건을 명시했다.
- 최초 검토에서 자료 계약과 하네스 입력 형식이 달랐고, 데이터 담당이 Java `schema_version` 봉투에 맞추어 다시 작성했다. 입력 형식 일치와 자료 진위·원장 감사는 별개이며, 검증기와 Java 양쪽에 실제로 같은 샘플을 넣은 결과를 최종 기록한다.

독립 검토자가 Python 계약 fixture를 변형하여 7가지 입력을 직접 실행했다. 정상 합성 입력은 구조만 통과하고 성과는 차단했다. 합성을 실제자료로 재명명, 미래 계좌 관측, 이전 자동매매 초기 상태, 허용되지 않은 주문 API, 알 수 없는 설정, 자격증명 필드는 차단했다. 7건 모두 `performance_allowed=false`, `returns_computed=false`이며 `INDEPENDENT_ADMISSION_CHECKS_PASS 7`로 종료했다. 이 검사는 Java 실행이나 시장자료 진위 검증을 대신하지 않는다.
