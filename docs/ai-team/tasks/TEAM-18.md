# TEAM-18 실제 시장자료 확보 및 생산 전략 성과 검증

- 상태: 공개자료 일부 확보·자료원 조사 완료. 시점별 입력자료 접근 및 체결 원장 구현 미완료로 수익률 검증 대기.
- 후속 갱신: [TEAM-19](TEAM-19.md)에서 실제 주문 기반 가상 체결·계좌 원장을 구현·검증했다. 아래 미구현 설명은 TEAM-18 종료 시점 기록이며, 시장자료 확보와 S&P 500 성과 비교는 여전히 미완료다.
- 시작일: 2026-11-19.
- 사용자 목표: 현금 한도와 계좌 고점 대비 10% 차단 정책을 유지하면서 실제 자동매매 코드로 S&P 500 대비 성과를 검증한다.
- 범위: 공개 자료 획득·출처/시점/누락 검사, 생산 코드 재생과 성과 계산의 연결 가능성 검토, 격리 검증. 운영 설정·주문·DB·push·배포 없음.
- 기존 변경: TEAM-10~17의 작업 트리를 보존한다. 이번 요청은 운영 활성화나 시장자료 구독 구매 승인으로 해석하지 않는다.

## 역할과 소유권

- 총괄/개발: 공개자료 획득 도구 및 실제 획득 실행, 통합 판정, 현황 갱신.
- 자료 기획: BE `tools/team18_sources.md`, 공식 제공처와 접근 조건·충족 범위 조사.
- 독립 검증: 이 작업 기록, 기존 실제 전략·재생 코드의 입력과 결과 경계 검토. Maven 실행은 총괄만 수행한다.
- 디자인: 제품 UI 변경이 없어 별도 화면 작업 없음.

## 성과 검증에 필요한 연결

1. 시장 입력은 각 판단 당시 이용 가능한 순위·시세·호가·거래량·기업 지표·지수 구성종목·완료 일봉이어야 한다. 다운받은 시각과 과거 이용 가능 시각을 구분하고 출처 원문 및 해시를 보존한다.
2. 실제 서비스의 후보·수량·위험·매도·대사 코드를 호출한다. 다른 ETF 연구 알고리즘을 이 전략의 성과로 보고하지 않는다.
3. 실제 생성 주문에서 모의 체결과 다음 현금·보유·미체결 상태를 생성하는 원장이 필요하다. 수수료·스프레드·슬리피지·체결 지연·부분체결·결제 가정을 사전에 고정한다.
4. 현금·보유평가·배당·기업행사·외부 자금 흐름을 연결한 전체 계좌 수익률과 최대 낙폭을 평가한다. 같은 기간·통화·평가 시각·배당 기준의 S&P 500 벤치마크와 비교한다. SPY를 사용하면 지수 자체가 아닌 ETF 대용치임을 표시한다.
5. 데이터 공백·자료 권한·실행 원장 미완성 중 하나라도 남으면 결과를 미검증으로 둔다. 단순 자료 다운로드 성공을 전략 수익률 검증 성공으로 표시하지 않는다.

## 독립 코드 검토

### 실제 서비스의 시간과 입력

- `KiwoomUsAutoTradeService.scheduledDecision()`는 10분 주기이며 `scheduledAccountAndExitSync()`는 30초 고정 지연 감시다. 일봉만으로 이 감시의 손절·계좌 위험 관측 시점을 재현할 수 없다. 시험에서 사용하는 정확한 일정과 실행 지연 가정을 명시해야 한다.
- 후보는 거래대금 순위 1~50 및 지수 편입 여부 등을 사용한다. 일부 유명 종목만 모은 일봉 표는 순위 모집단의 대체물이 아니다.
- `KiwoomUsFundamentalService`는 Yahoo forward PE를 우선 사용하고 trailing PE로 대체할 수 있으며 ROE도 사용한다. 1일 정상 캐시와 7일 과거 캐시 대체 동작이 있다. SEC의 과거 재무제표 확보만으로 당시 Yahoo 전망 PER 및 실제 캐시/조회 상태가 복원되지는 않는다.
- `KiwoomUsIndexUniverseService`는 Wikipedia의 두 지수 구성종목 표와 최대 7일 캐시를 사용한다. 현재 구성종목을 모든 과거 시점에 적용하면 생존편향이 생긴다. 공식 지수 이력과 실제 당시 캐시 상태도 동일한 개념이 아니다.

### TEAM-17 하네스와 성과 원장의 차이

- `KiwoomUsProductionReplayHarness.run()`은 입력 프레임의 계좌와 broker 응답을 공급한다. 생성된 매수·매도에서 다음 프레임 잔고를 자동 계산하는 체결 엔진은 아니다.
- 그러므로 실제 시세를 합성 시나리오에 넣거나 `dataset_kind`를 바꾸는 것만으로는 수익률 검증이 되지 않는다. 입력의 계좌·체결과 실제 주문 사이의 인과 관계를 별도 감사해야 한다.
- 신규 가상계좌로 실험할 경우 개인 실계좌의 과거 주문 이력은 필수 시장자료가 아니다. 초기 현금, 기존 보유 수량/원가, 새 위험 기준, 이전 자동매매 이력 없음이라는 가정을 명시하고 이후 상태를 실제 결정에서 생성할 수 있다. 이는 현재 실계좌의 운용 이력을 복원한 결과와 구분한다.
- 실제 보유 계좌의 결과를 주장하려면 해당 계좌의 시작 상태와 자금 흐름이 필요하다. 이번 작업에서 운영 계좌 조회나 위험 기준 초기화를 수행하지 않는다.

## 새 자료 도구 검증 항목

- HTML 오류/403/429 응답, 빈 JSON, 요청기간 공백을 데이터 확보 성공으로 취급하지 않는다.
- 응답 원문 해시와 메타데이터를 연결하고 재실행 시 기존 원문을 조용히 덮어쓰지 않는다.
- 현재 snapshot, 개별 기업 표본, 수정된 최신 재무값은 과거 전체 모집단 자료로 승인하지 않는다.
- 자료가 없다는 이유로 정상 조회 또는 `DATA_UNAVAILABLE`을 만들어 생산 필터를 우회하지 않는다.
- 입력 파일을 통한 비밀정보 전송, 인증 정보 출력, 운영 주소 쓰기 요청을 하지 않는다.
- 벤치마크만 확보되어도 전략 수익률 0% 또는 초과수익을 계산하지 않는다.

## 실행 결과

BE `tools/team18_acquire.py`를 추가했다. 고정된 SEC 공개 주소 4개에만 GET하며 인증·운영 계좌·DB를 사용하지 않는다. 요청 간 1초 이상 간격, 응답 30MB 상한, redirect 거부, 실행별 새 폴더, 오류 메시지 민감정보 제거를 적용했다. SEC 원문은 현재 내려받은 공시 집계이며 당시 Yahoo 조회 결과로 변환하지 않는다.

## 독립 검증 최종 기록

- 초기 수집기에서 빈 taxonomy/units 및 빈 제출 목록이 자료 확보 성공으로 집계되는 결함을 재현했다. 개발 담당이 비어 있지 않은 기록, 공시일/기간일, accession 및 수치/접수시각 배열 검사를 추가했다.
- 수정 후 독립 변형 7건(빈 taxonomy, 빈 units, 빈 submissions, 잘못된 taxonomy 자료형, 잘못된 root, 원문 덮어쓰기, 크기 초과)을 실행해 모두 실패폐쇄 및 기존 원문 보존을 확인했다. 출력: `INDEPENDENT_MUTATION_PASS 7`.
- `python -B -m unittest team18_test.py`를 BE tools에서 독립 실행: 12개 통과. 네트워크 요청은 추가 실행하지 않았다.
- 성공 폴더 원문 4개의 manifest SHA-256·바이트 수와 기업 CIK를 확인했다. 최종 수정 수집기의 `summarize()`로 모두 재검사 통과했다. 획득 당시 manifest와 원문은 수정하지 않았다.
- 수집기는 고정 SEC 주소만 GET하고 redirect를 거부한다. 기존 raw 파일을 덮어쓰지 않으며 운영 연결·인증 키 옵션은 없다. 수집 manifest는 `performance_allowed=false`, `returns_computed=false`를 유지한다.
- 정적 서비스 검토, 수집 도구 및 실제 확보 원문 검사는 완료했다. 새로운 생산 서비스 재생·인과적인 체결 원장·S&P 500 수익률 비교는 미검증으로 남긴다. 시장자료 접근권과 성과 엔진 구현은 서로 다른 후속 조건이다.
