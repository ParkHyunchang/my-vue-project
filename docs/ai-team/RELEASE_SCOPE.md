프론트 모의매매 노출은 `VUE_APP_US_PAPER_ENABLED=true`를 명시한 별도 빌드에서만 허용한다. 이 옵션만 켜서는 서버 API가 활성화되지 않는다. 운영에서는 켜지 않으며, 독립 `scripts/paper-local.cjs` 실행은 기존 흐름을 사용한다.

연구 전략은 등록·승인만으로 자동매매를 시작하지 않는다. 연결이 활성화된 뒤 승인 전략으로 운용하면 대상 SPY/QQQ/GLD/IEF 밖의 기존 보유는 다음 실행에서 매도 계획에 포함될 수 있다. 승인 철회/비활성화로 기존 전략에 자동 복귀하지 않는다. 최신 TEAM-31 기록의 승인 가능 후보는 0개다.

## 배포 순서와 남은 준비

1. 양쪽 변경을 검토하고 커밋 해시를 확정한다. `main` 푸시는 자동배포를 유발하므로 연구 코드 보관만을 위한 푸시와 구분한다.
2. 배포 직전 프론트 격리 테스트/lint와 백엔드 JDK21 `test-isolated.ps1 -Verify`를 확인한다. 기존 검증 기록은 현재 버전의 배포 검사를 대신하지 않는다.
3. 자동매매의 실행/미확정 주문 상태를 확인하고 운용을 정지한 유지보수 시점에 진행한다. 계좌 위험·승인·주문 이력은 초기화하지 않는다.
4. 운영 DB 백업과 스키마 변경을 검토한다. 신규 Entity는 위험·입출금 2개, 전략 승인·감사 2개, 모의매매 4개다. 기능 비활성화와 Entity 스캔은 별개이므로 비활성 기능의 테이블도 만들어질 수 있다. 기존 holding/proposal의 신규 컬럼도 확인한다. 현 docker 프로파일의 `ddl-auto: update`는 서버 기동 시 변경을 적용한다.
5. **백엔드 먼저** 배포하고 기동·DB·신규 API의 ADMIN 권한/비활성 상태를 확인한다. 이어 프론트를 배포해 위험 패널·오류 표시·모의매매 탭 기본 숨김을 확인한다.
6. 실제 계좌 응답과 새 필드 검증의 호환성을 확인한 뒤 사용자가 별도로 위험 정책을 확인하고 운용 여부를 결정한다. 이번 변경만으로 자동매매 시작·연구 연결 활성화를 수행하지 않는다.
