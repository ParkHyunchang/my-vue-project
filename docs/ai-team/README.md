# AI 팀 운영

두 저장소를 하나의 제품으로 관리한다. 사용자 요청을 총괄 AI가 기획·디자인·개발·검증 업무로 나누고 결과를 통합한다. 이 문서는 지속적인 작업 지침이며 상시 실행 서비스나 예약 작업을 설치하지는 않는다.

## 시작하기

- 현황과 제한: [STATUS.md](STATUS.md)
- 다음 업무와 완료 기준: [BACKLOG.md](BACKLOG.md)
- 작업 기록 양식: [TASK_TEMPLATE.md](TASK_TEMPLATE.md)
- 역할: [기획](roles/planning.md), [디자인](roles/design.md), [개발](roles/development.md), [검증](roles/verification.md)
- 격리 실행 안내: [프론트](../../TESTING.md), [백엔드](../../../my-vue-project_backend/TESTING.md) (백엔드 링크는 형제 폴더 체크아웃 기준)

사용자는 이 채팅에 `TEAM-01부터 진행해줘` 또는 `구독 관리에 알림 기능을 추가해줘`처럼 요청하면 된다. 총괄이 업무를 구체화하고 필요한 역할을 배정한다. 중간 구현 선택은 기존 기준에 맞춰 진행하고 제품 목적·대상 사용자가 불명확할 때 필요한 질문만 한다.

## 역할과 작업 순서

| 담당 | 입력 | 결과물 | 인수 조건 |
|---|---|---|---|
| 기획 | 사용자 목표, 현황, 제약 | 문제/범위/완료 기준, 권한·오류 흐름 | 개발과 검증이 같은 완료 기준을 사용할 수 있음 |
| 디자인 | 기획 기준, 기존 화면 | 화면 흐름, 상태별 UI, 반응형·접근성 명세 | 기존 컴포넌트 재사용과 변경 위치 명시 |
| 개발 | 합의된 범위와 UI/API 계약 | 구현, 필요한 회귀 테스트, 변경 설명 | 관련 검증 결과와 잔여 문제 전달 |
| 검증 | 완료 기준, 실제 diff | 요구사항별 통과/실패/미검증, 재현 근거 | 결함 수정 후 영향 범위 재검증 |
| 총괄 | 모든 역할 결과 | 통합 diff, 작업 상태, 사용자 보고 | 미검증 항목을 완료로 포장하지 않음 |

기획과 현재 UI 조사는 병렬 진행할 수 있다. 디자인은 기획 범위를 확인한 후 확정한다. 구현은 계약 확정 후, 최종 검증은 실제 구현 후 수행한다. 검증 담당의 사전 테스트 설계는 병렬 진행 가능하다.

현재 세션은 총괄 포함 동시 4개 에이전트를 지원한다. 총괄이 개발 역할을 겸하거나 분석 역할 종료 후 개발 담당을 배정한다. 슬롯 수는 세션마다 확인하며 무한 병렬 실행을 가정하지 않는다. 여러 에이전트가 같은 파일을 동시에 수정하지 않도록 총괄이 소유 파일을 배정한다.

## 총괄의 실행 절차

1. 양쪽 Git 상태와 관련 지침을 읽고 업무 ID를 선택한다.
2. `tasks/<ID>.md`에 템플릿을 복사해 목표, 범위, 완료 기준, 담당 파일을 작성한다.
3. 역할 문서 내용과 작업 맥락을 서브에이전트에게 전달한다. 역할 이름만 전달하지 않는다.
4. API가 바뀌면 경로/메서드/요청/응답/인증/오류/하위 호환성을 먼저 기록한다.
5. 개발 결과를 통합하고 검증 담당이 요구사항과 diff를 대조한다. 결함은 재현 근거와 함께 개발 담당에게 돌려보낸다.
6. 완료 조건을 충족하면 업무 목록과 작업 기록을 갱신하고 사용자에게 결과를 보고한다. 환경 때문에 필수 검증을 못했으면 `검증 대기`로 남긴다.

서브에이전트 도구가 없는 환경에서는 동일 역할을 순차 적용하되 독립 검토가 아니었음을 기록한다. 역할 정의 파일은 Codex의 전역 설정을 변경하거나 별도 모델을 등록하지 않는다.

## 완료와 운영 반영

- 상태: `대기 → 진행 → 검증 → 완료`; 의존성은 `보류`, 환경 제한은 `검증 대기`와 이유를 기록한다.
- 완료 기준 충족, 관련 테스트, 프론트·백엔드 호환성, 미검증 범위 설명이 있어야 구현 완료다.
- 운영 배포는 별도 상태로 기록한다. 현재 양쪽 저장소는 main push로 배포되므로 문서 커밋도 배포를 유발할 수 있다.
- 운영에 반영할 때는 두 저장소의 버전, 배포 순서, DB 변경 여부, 확인 항목과 되돌릴 버전을 기록한다.
- 정기 운영은 추후 로그/지표 연결과 일정이 정해진 경우 구성한다. 지금은 요청에 따라 개발하고 결과를 남기는 체계다.
